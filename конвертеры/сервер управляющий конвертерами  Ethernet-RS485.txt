Нативное Node JS серверное приложение  для управления работой конвертеров Z-397 web (RS485 в Eternet). 

Решаемые задачи:
1) поиск веб конвертеров Z-397 web (RS485 в Eternet). 
Используется широковещательный запрос UDP, в ответ конвертеры отправляют информацию о себе. Подробнее в прикрепленном файле.
2) Подключение конвертеров работающих в режиме клиент и  настроенных на работу с серавером (присылают запросы)
3) Переключение скорости передачи конвертера на выбраннуюю. После этого конвертер поддерживает протокол NVT, что означает маскирование FF.
4) Для управления сервером есть два типа каналов связи
- post запросы на сервер
- внутренний объект.  


Список серверов
- Сервер UDP для поиска конвертеров, отправляет широковещательные запросы
- Сервер TCP socket для подключения конвертеров как клиентов
- Клиент TCP socket для подключения к конвертерам серверам
- Сервер HTTP для показа HTML страниц управляющих приложением через POST запросы 
- WEBSOCKET для двухсторонней связи с HTML страницами


В консоли приложения выводиятся:
- локальный адрес и порт,  сетевой адрес  и порт для открытия главной страницы, если у компьютера несколько сетей, значит выводится  несколько адресов.
- локальный адрес и порт,  сетевой адрес  и порт для подключения конвертеров в режиме клиент.
- лог событий и ошибок (включается и выключается  командой)

Структура HTTP сервера 
index.html
	/pages - для HTML страниц
	/stands - для хранения JSON файлов
	/cmd - для хранения JSON файлов
	/lists - для хранения JSON файлов

Главная страница index.html предназначена для показа ссылок и описаний страниц находящихся в папке /pages
Ссылки и описания создаются автоматитечки на основе названия файла и информации в поле Title каждой странице, обновление выполняется по нажатию кнопки на странице index.html

Для взаимодействия каналов связи с конвертером для каждого конвертера создается очередь команд (объект очереди).
По этому, создаем класс создающий такие объекты.
Конвертер  работает по принципу Запрос-Ответ. 
Если ответ не получен в течении заданного времени,  считается, что ответ не получен.
Задача объекта организовать очередь выполнения команд.
Очередь состоит из двух списков основного и оперативного. Списки это Set().
Сначала выполняются команды оперативного списка, потом команда основного списка,  если оперативный список пуст выполняется следующая команда основного списка.
Когда оба списка пусты в канал ни чего не отправляется.
Для добавления команд в очередь объект имеет метод add. При его вызове указывается в какой из списков нужно добавить команду.
Добавлять команды в очередь можно в любой момент. 
Если  очередь пуста, то как только в очередь добавляется  команда, очередь, начинает обрабатываться.
Необходимо предусмотреть настройку паузу после получения ответа до отправки следующего запроса.
В класс передается указатель на функцию отправки сообщений.
В объект, метод add передаются:
- тип списка (основной или оперативный)
- ссылка на экземпляр команды (функция генератор =  function *)
- calback для отправки ответа каналу который  добавил команду в очередь
- время ожидания ответа, после которого считается, что ответа нет
В объект, метод listener передаются сообщения (ответы) коннвертера.

Протокол связи с приложением:
JSON строка объекта
api: api,
cmd: cmd,
data: {
name:value,
....
}
Каждая страница имеет свое название для api, соответстующее ее названию (для admin.html будет admin)
Для каждого api создается свой объект с функцими.
При получении команды приложение проверяет соответстующий api объект на наличие указанной cmd = функции,
если ее нет то сообщает - функция не найдена
если есть то вызывает ее с параметрами из data.
Каждая такая функция добавляет команду в очередъ.
Ответ на запрос, функция выполнена.
После выполнения команды приложение пересылает обработанный ответ конвертера.
Ответ конвертера отправляется только тому каналу, который вызвал функцию добавления в очередь.



В папке /pages создается страница admin.html,  Title =  Управление конвертерами
(остальные страницы будут созданы позже, проект создается частями)
Страница admin.html состоит из трех вертикольных блоков 
1) Слнева окно для  списка конвертеров, показывается IP адрес
Возможностями CSS выделяем 
- подключен, не подключен (но на связи = активен),
-  не активен конвертер, 
- режим работы клиент или сервер, 
- удален (автоматическиподключение не восстанавливать).
- подключен к другому приложению (серверу) (подключиться не получится)
2) По центру окно для вывода запрашиваемой информации^
При клике по конвертеру (адресу), в левом окне,  открывается окно с информацией о конвертерев верхнней части этого окна кнопки:
-  подключить/отключить, 
- выпадающий список выбора скорости, команда смены скорости отправляется сразу. Варианты (230400 - по умолчанию,  115200, 38400)
- информация. Отправка запроса информации о конвертере = 0x69  0x0D.
- удалить конвертер (автоматически не восстанавливать соединение)
3) Справа окно с кнопками управления:
- включить/выключить вывод лога
- включить/выключить поиковые UDP запросы
